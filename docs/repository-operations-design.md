# Repository operations for Albumary

This is the historical implementation plan for the repository extraction from commit `53218d3`. The extraction is now implemented; see the [data-layer guide](data-layer.md) for current ownership and transaction behavior. The operation names and migration steps below describe the original target, not a separate pending migration. The plan builds on the [database package layout](database-organization-design.md) and [import workflows](imports.md).

## Ownership and entry points

Use three entry points for the work currently collected in `SqliteStateRepository`. All accept the caller's SQLAlchemy session. Two also take the resolved profile. None opens a database or looks up the default profile as a constructor side effect.

| Proposed entry point under `backend/app/database/repositories/` | Owns | Primary callers |
| --- | --- | --- |
| `AlbumCatalog(session)` in `album_catalog.py` | Shared `Album` identity, metadata, art selection and updates, global key search, physical cleanup of eligible album IDs | Library writes, metadata maintenance, artwork jobs |
| `AlbumLibrary(session, user)` in `album_library.py` | Membership, listens, feedback, library reads, user-scoped merge and removal. Coordinates catalog writes and credit projection where an operation changes shared metadata. | Album routes, manual activity, scoped metadata refresh, import matching and review |
| `AlbumStateRepository(session, user)` in `album_state.py` | Read or replace the complete state for a profile, including the tracking cursor, partial sessions, recent album keys and collection reconciliation | State routes, export, tracking, root `utils.py` |

The caller resolves the user once. Ownership checks already return a `User`, a worker already has `import_session.user`, and tracking already loads the eligible profile. Only default entry points that currently ensure a default profile should call `UserRepository.ensure_default_user()`. The default *authorized* album routes must continue to require an existing owner in the same session. Import history, log and diagnostics code that only needs an ID should receive the resolved profile ID.

SQL-free normalization and record formatting can live in `album_records.py`. Extract cohesive module-private library query and mutation helpers if needed during migration. A helper receives the actual session and profile ID it needs. The library owns the committed album command and stages the credit projection through `CreditRepository` in the same session. Catalog field-writing primitives stage data. The maintenance key-refresh path uses the same staged assignment and projection. Leave existing import functions and specialist repositories in place where they already give callers the intended operation. This design requires no base repository, generic filters, mappers for every table, DI registry, schema changes or new persistence framework.

## Album operations and consolidation decisions

| Current operations | Target and consumer contract |
| --- | --- |
| `completed_album_keys`, `find_completed_album_key`, repeated global key/ID fetches | `catalog.list_keys()`, `catalog.find_for_refresh(artist=…, title=…, key=…)`, `catalog.require_by_id(id)`. Return sorted strings, one attached album, and one attached album respectively. Keep explicit key, exact artist/title, then optional case-insensitive field matching and ambiguity errors. The maintenance loop snapshots keys before writes because refresh can rename or merge them. Fetch once when resolving a single target. |
| `get_completed_album_record`, `get_completed_album_record_by_id`, `_album_record`, `_album_record_for_update` | One `library.record_for(album)` formats display metadata with current-profile listens, tags, rating and notes even when a catalog lookup found a nonmember. `library.require_member(id)` is a separate check that returns the loaded album. Keep the by-ID route membership check before a remote refresh where it exists and the ownership checks at write time. Catalog merge/patch needs stored remote image fields and private identity separately from display serialization. |
| `library_album_records`, `get_library_album_metadata`, `_load_completed_albums` | Use `library.list_records()` for full profile state, `library.matching_albums()` for import's bulk artist/title-to-ID and metadata index, and `library.find_metadata(artist, title)` for one diagnostic lookup. The importer consumes tracklist and matching metadata and needs no per-album feedback/listen queries. Preserve matching keys, duplicate-title selection and stored metadata fields used by matching. Keep the diagnostic case-fold query and missing-record result. Full-state reads preserve sorted keys, ordered listens, the raw-blob fallback for malformed JSON, hidden manual identity and local image preference. |
| `_resolve_album_identity`, `_resolve_manual_input_identity`, `_new_album_key`, two create/enrich paths | `catalog.resolve_identity(record)` checks release-group identity, then compatible normalized artist/title, including pending albums under disabled autoflush. `library.find_manual_input(record)` stays membership-scoped. `catalog.enrich_or_create(record, resolved_album)` applies the same merge rules once and flushes when an ID is needed. On collision with conflicting authoritative IDs, preserve the suffixed key. Snapshot resolves all existing identities before removing stale entries and re-resolves new ones during insertion. | `create_completed_album` + `…_with_changes`, `add_album_listen` + `…_with_changes` | `library.add_album(record, listen_date=None)` and `library.add_listen(album_id, listened_at)`. One result per method holds the returned record and existing `AlbumChange` facts. Manual service derives events after commit. Review consumes the record. Candidate application can use the ID or discard the result. Both preserve implicit membership creation for a shared album. |
| `update_user_album_tags` + `…_with_changes`, `update_user_album_feedback` + `…_with_changes` | `library.set_tags(id, tags)` and `library.set_feedback(id, rating, notes)`. Keep the record and named action-specific outputs for tag additions/removals or rating/note change types. Both require membership. Normalizing legacy tags and replacing nullable feedback are distinct operations. Keep before/after evaluation inside the write lock for manual updates. |
| `_user_has_album`, `_user_album_membership`, `_add_user_album`, `_add_listen`, `album_listen_timestamps` in import events | One scoped membership lookup, `ensure_membership` with created flag including pending objects, and an exact-timestamp insert primitive. Remove the unused alternate user override after migrating callers. Centralize `library.listen_timestamps(id)` for the same profile/album. Sorting suits state serialization and preserves UTC-date membership tests. Import date parsing stays in `candidate_results.py`. Snapshot history reconciliation retains its set-based diff and in-memory dedupe. |
| `update_completed_album_fields`, key refresh, by-ID refresh, `merge_completed_album_listens` | `library.patch_metadata(id, fields)`, `library.replace_metadata(id, record)`, and `library.merge(source_id, target_id)` serve profile writes. `library.replace_catalog_metadata_for_refresh(key, record) -> str` re-reads the album by key after remote lookup. This may update an unowned catalog album on the no-merge path. Its merge branch invokes the scoped merge and the by-ID variant returns a record. Key refresh enriches the target before the merge checks both memberships, while by-ID refresh checks both before enrichment. Keep transaction/error behavior during extraction. |
| `delete_completed_album`, `delete_album_listen`, `_sync_completed_albums` stale deletion | `library.remove_album(id) -> AlbumChange`, `library.remove_listen(id, timestamp) -> (record, change)`. Share the scoped bulk deletion of listens and memberships with snapshot replacement and merge, after each has done its own validation and import-link handling. Removing a listen leaves membership intact. A merge combines tags, prefers target feedback, remaps this profile's imported album references and removes the source membership. |
| `import_album_state`, `save_album_state`, `load_album_state` | `state.replace(snapshot)` and `state.load()`. Retire the identical import alias after migrating fixture callers. Replace can prune missing albums, listens and in-progress entries. Preserve per-profile annotations, the first history replacement followed by additional histories for multiple input records resolving to one ID, and conditional rebuild of changed credit sources. Keep cursor, partials, collection and credit changes in one commit. |
| `albums_for_artwork_cache`, `albums_for_artwork_backfill`, both artwork setters; import-session album-ID lookup | `catalog.artwork_inventory()`, `catalog.artwork_backfill_candidates(ids=None, limit=None)` share one projection ordered by album key. Preserve the existing truthy-ID branch which returns selected rows even when already complete, and the empty/omitted-list branch which filters for missing remote artwork plus an MBID. `catalog.set_remote_artwork(id,url)` updates both remote fields, and `catalog.set_local_artwork(id,path)` only the local path. Put `linked_album_ids(session, import_session_id)` on `import_event_repository` for the worker's sorted distinct non-null IDs. |

A single bulk projection should replace the current full-state per-album membership/history reads once equivalence is established. Join memberships to shared album columns, including the binary metadata projection, and fetch ordered listen timestamps for the profile separately. This avoids duplicating metadata per listen. Preserve empty membership-only albums and ordered history. Single-album commands can use indexed reads. Keep public and credit queries as independent projections with their own ordering, predicates and payloads.

## Transactions and failure behavior

- Preserve the app's session factory, worker-owned sessions, one standalone engine per job, and fresh sessions per profile and for recording a tracking failure. ORM records expire on commit and autoflush is disabled. Pass real attached objects only inside the session that owns them. Never move remote lookup or file downloads inside the manual SQLite write lock.
- Keep the existing committed library commands while extracting reusable primitives. Private primitives stage writes and flush when required for IDs, foreign keys or follow-up queries. Manual commands take `BEGIN IMMEDIATE` after enrichment, capture facts atomically, commit, then publish logs. Preserve the import path's lack of manual events and avoid introducing extra membership queries to compute change facts.
- Keep the standalone tracking snapshot commit before its separate successful-sync credential update. Remote artwork commits before optional file caching and the later local-path update. A metadata/credit or library merge command commits once, including any duplicate resolution.
- Preserve source queue commit before dispatch, source/progress checkpoints, persisted candidates, per-unique-album enrichment, terminal status/summary/log and separate post-completion artwork. In `candidate_results._apply_listen`, add/create commits the whole shared session **before** the caller stages the current candidate result. `review.resolve_review_item` commits library writes and optional feedback before the final reviewed-row commit. Moving either commit to the end would change crash/retry behavior. `history.delete_import_session` owns exactly one cleanup commit.
- Create, patch and refresh rebuild the affected album's credit projection. Snapshot replacement compares credit source signatures and batches only changed IDs. Preserve the standalone rebuild's current no-source no-write behavior.

## Data integrity work to schedule separately

These are observable policy or recovery questions. Preserve current behavior during operation extraction. Each needs its own expected outcome and failing fixture before changing writes.

1. **Import provenance and recovery.** Import delete infers owned listen keys from every linked imported event's album ID and timestamp. Last.fm uses multiple events per derived listen. A timestamp could coincide with an independent listen. Deleting an import can also remove a membership with feedback if it has no remaining listens. Exercise both cases, and interruption after the library commit but before a candidate is marked processed. Decide ownership and retry semantics before designing a fix.
2. **Foreign keys in destructive workflows.** Album deletion can encounter imported-event references. Profile deletion bulk-deletes the user after deleting selected child tables, bypassing ORM cascades for other import, OAuth and ownership records. Test populated dependencies with foreign key checks enabled. Specify which rows must be removed, detached or retained and what the result counts mean.
3. **Pending duplicate listens and manual aliases.** With autoflush disabled, an add can receive the same timestamp in `listen_date` and `listen_history` or more than once in a history. Exact-timestamp checks against persisted rows miss a second pending listen. Also verify manual alias retention across a generic patch/enrichment that starts from a display record filtering `_manual_input_identity`. Use separate targeted fixes for behavior on these inputs.
4. **Metadata refresh and merges.** In a multi-album maintenance run, a key-based duplicate refresh can modify a target before a scoped merge fails. Investigate rollback between iterations. Merging recreates listens using the target album's source and can change provenance. Preserve these distinctions in extraction, then decide how maintenance should handle cross-profile conflicts, per-album failures and source history.
5. **Concurrent snapshot replacement.** Tracking reads a whole profile and later replaces it, potentially removing a manual or imported listen added in the meantime. A delta-write or concurrency policy changes tracking behavior and needs its own concurrent two-session fixture.

## Implementation slices and acceptance

1. **Establish a baseline.** Run `make test`. Characterize gaps before extraction, particularly exact vs normalized slug lookup, empty artwork ID selection, unowned key refresh, strict import orphan eligibility, and interruption between a library write and marking the import row. Use file-backed temporary SQLite for cross-session visibility. Compare snapshots, affected IDs/counts and which rows are durable after each checkpoint.
2. **Unify low-risk operations.** Move exact profile lookup, resolve profile once, move the shared key formatter and scoped timestamp read, unify the two identical orphan policies and artwork projection. Keep compatibility wrappers temporarily where broad caller migration would obscure a diff. Run profile authorization, public activity, credit intelligence, artwork, admin-user and import cleanup tests.
3. **Extract catalog writes and library commands.** Migrate manual services, both album route families, metadata maintenance, credit and dedupe scripts. Move one paired mutation at a time. Update direct tests to inspect named results. Run SQLite state, multi-user state, API album actions, manual activity concurrency/failed-commit, credit facts, dedupe and metadata refresh tests after each slice.
4. **Separate snapshot and import reads.** Migrate root utilities, runners, API state/export, import candidate application, diagnostics, history/review and post-import artwork. Replace per-album hydration with batched projections in their own diff. Compare payloads on shared albums with distinct profile feedback/listens, invalid metadata, local artwork, no listens and duplicate display names. Count statements on a growing library. Full snapshot and matching reads must avoid linear per-album queries. Verify matching does not read feedback or listen history. Keep the raw and candidate insert batching tests, mock all remote calls, and compare recovery and deletion against fresh sessions.
5. **Retire adapters.** Search the entire tree, including scripts, fixtures, monkeypatch paths, docs and root modules, for `SqliteStateRepository` and the removed methods. Migrate in-tree references, then remove forwarding-only methods. Update the live data-layer guide. Run `make test`, exercise maintenance dry-runs on a temporary database and check that API shapes, schema, progress statuses, transaction behavior and manual event payloads remain stable.
